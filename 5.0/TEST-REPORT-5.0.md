# Грави-Бум! 5.0 — отчёт проверок

Дата: 26.09.2026. Среда: Chromium / Playwright, WebGL SwiftShader. Это автоматизированные браузерные проверки и осмотр снимков, не испытания на физическом телефоне.

## 1. Сравнение контакта 4.9 и 5.0

Для измерений использовались изолированные физические сцены с настоящими функциями игры: оставлялись нужный пол и тестовые шары, отключались посторонние препятствия. Проверка расстояния до поверхности выполнена отдельным геометрическим расчётом. Координаты — в единицах игрового мира.

| Проверка | 4.9, измерено в сравнительном прогоне | 5.0 |
|---|---:|---:|
| Максимальный вертикальный размах покоя, 20 с | 0,00203834 | 0 |
| Максимальный непрошеный горизонтальный сдвиг, 20 с | 3,2475762 | 0 |
| Наибольшее проникновение при качении по профилям | 0,42884181 | менее 1,3×10⁻¹⁵, округление |
| Проникновение нижнего шара в пол после контакта пары | 0,02559854 | 0 |
| Разброс конечной координаты при разном шаге кадра, 2 с | 0,00645957 | 0 в выбранном сценарии |

Последний пункт — движение по ровному наклонённому полу с шагами кадра 1/30, 1/60, 1/120 и 0,1 с. Это не утверждение о тождественности любой произвольной последовательности кадров или о реальном FPS устройства. Значения старого дрейфа могут меняться между прогонами из-за прежних случайных импульсов.

### Объём контактных тестов

- Белый шар: 3 плоских этажа × 3 частоты, по 20 секунд покоя. Нулевые дрейф/дрожание/скорость после установки на опору.
- Качение: 4 этажа × 3 частоты, контроль зазора относительно профиля чаши, плоскостей и смещённой финальной воронки.
- Два шара один над другим: 3 частоты, по 5 секунд. Нижний шар не остаётся внутри пола.
- Цветные сферы: радиусы 0,45 / 0,62 / 0,95, 4 этажа × 3 частоты = 36 сценариев. Максимальный сдвиг около 6,8×10⁻¹⁵. Для покоя на финальной наклонной поверхности её уклон компенсировался наклоном башни; в обычной игре шар по ней закономерно катится.
- Въездной пандус → площадка жёлоба → выходной пандус: 4 шага кадра, включая 0,1 с. Все маршруты пройдены; проникновение не выше погрешности округления.
- Оба пандуса: концы верхней грани видимого наклонённого бокса и расчётного отрезка совпадают с ошибкой менее 2×10⁻¹⁵.

Это проверки конкретных сцен, а не исчерпывающий перебор всех контактов башни. Реальные удары по-прежнему вызывают отскок; положительный зазор во время полёта не считается ошибкой.

## 2. Удаление датчиков и обычное управление

Проверены размеры 1280×800, 393×851, 320×640 и 851×393.

- Нет кнопок датчика/калибровки и прежних DOM-элементов, нет GB.Motion.
- В собственном игровом JS отсутствуют DeviceOrientationEvent, DeviceMotionEvent, GravitySensor, requestPermission, deviceorientation и devicemotion.
- С инструментированными API загрузка и переходы не регистрируют слушателей датчиков и не запрашивают разрешения.
- В справке RU/EN не осталось инструкций включить датчик или откалибровать устройство.
- Меню/справка показывают 5.0; версия в подписи автора обновлена.
- Перетаскивание мышью меняет наклон; пауза/возврат работают.
- Отдельно через эмуляцию touch-событий CDP проверены один палец для наклона, два пальца для поворота и изменения масштаба.
- Клавиатурное разрезание троса и запуск обучения работают.
- Визуально просмотрены мобильное меню и игровой HUD: пустой блок удалённой кнопки не остался.

CSS orientation для адаптивной компоновки и prefers-reduced-motion оставлены намеренно: это не датчики движения.

### Дополнительная проверка Авто — не всё успешно

Первый этаж проверялся вместе с магией, без принудительного заполнения лунок. В одном расширенном прогоне 5.0 решены 8/10 вариантов; варианты 5 и 8 дошли до штатной ситуации нехватки шаров. В отдельных других прогонах вариант 5 решался. В сравнительном прогоне 4.9 также была неудача — вариант 9. Это неполная статистика, из неё нельзя делать вывод о проценте надёжности помощника.

На третьем этаже варианты 1 и 5 решены Авто; вариант 10 дошёл до предложения перезапуска как в 4.9, так и в 5.0. Исправление контакта с полом не делает стратегию Авто безошибочной. Эти проверки не включены в перечень полностью успешных серий.

## 4. Прогресс и сборки

- Старые общие очки не приписываются честной категории; fairScore и autoScore сохраняются независимо.
- Использование Авто остаётся отмеченным после выключения и сброса этажа.
- localStorage и объединение тестовой облачной структуры сохраняют независимые максимумы.
- Сброс этажей 2/3/4 возвращает игрока на соответствующий старт и сохраняет уже пройденные этажи.
- SDK-заглушка: язык, ready, start/stop и реклама с приостановкой/возобновлением — пройдены.
- Автономный HTML открыт через file:// без SDK.
- Синтаксис игрового JS, уникальность DOM id, отсутствие удалённых меню и сенсорных элементов — проверены.
- ZIP проверены на целостность; index.html публикационной сборки находится в корне.
- В перечисленных успешных браузерных сериях ошибок JavaScript не зафиксировано.

## Ограничения

Нет испытаний на физических Redmi/iPhone, в Safari, измерений аппаратного FPS/нагрева, настоящих рекламных callbacks или облачного аккаунта. Полная кампания вручную не проходилась. Тесты подготовленных состояний не выдаются за ручное прохождение. Сборка требует пользовательского тестирования на целевых устройствах перед публикацией; модерация не гарантируется.
