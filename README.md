# ГРАВИ-БУМ! v4.0 — Техническое задание

## Часть I. Что делаем и что должно получиться

### I.1. Что такое «Грави-Бум! v4.0»

«Грави-Бум!» — это казуальная браузерная 3D-аркада на физике, выполненная в одном HTML-файле без серверной части и без внешних ресурсов (всё — процедурно). Игрок управляет наклоном стеклянного «стакана», в котором сверху вниз спускается белый игровой шар. На пути шара — четыре этажа с загадками, каждая из которых требует своего типа мышления: пространственного, физического, математического и тактического.

Текущая версия 3.5.0 — это одна большая вертикальная аркада с четырьмя уровнями среды (чаша → воронка → ядро → кнопка), магией match-3, ловушкой, реплеем, настройками баланса и локализацией RU/EN. Игровой цикл — «наклони стакан, разрежь трос, доведи шар до кнопки, по пути реши головоломки».

### I.2. Что должно получиться после v4.0

**Первое.** Каждый уровень игры делится на **четыре последовательных этажа**, каждый с собственной загадкой:

- Этаж 1 «Чаша» — **цветные числовые лунки**: закатить в каждую лунку нужное количество шаров нужного цвета.
- Этаж 2 «Труба» — **две параллельные цепочки шаров в жёлобах**: закатить игровой шар в спусковой люк, чтобы запустить цепочку; цепочка должна докатить до мишени нужные шары и не зацепить мины.
- Этаж 3 «Резонанс» — **три квадратные плиты на полу**: ударить в каждую игровым шаром с нужной скоростью (слабо, средне, сильно). Плиты деактивируются при случайном ударе другим шаром.
- Этаж 4 «Ядро» — **финальная загадка v3.5**: разбить фиолетовое ядро щита и попасть на кнопку.

**Второе.** В игре **десять уровней сложности**. Каждый уровень содержит все четыре этажа в фиксированном порядке. Уровни различаются плотностью правил: на первом — только одна лунка, только одна цепочка, только одна плита; на десятом — пять лунок, две дороги по 8 шаров с минами и смещением, четыре плиты с узкими порогами и два шара-помехи.

**Третье.** Каждый этаж получает **свою цветовую палитру**, плавно переходящую при спуске между этажами. Палитра — часть визуального языка прогресса.

**Четвёртое.** **Магия становится каскадной**: если цепочка из трёх и более шаров взрывается и в радиусе до 3.5 юнита есть ещё шары того же цвета, они тоже взрываются — «эхом», со сниженным счётом и без дальнейшего каскада.

**Пятое.** Игра получает **законченный мета-цикл**: главное меню с сеткой из 10 уровней, звёзды 0–3 за уровень, рекорд очков, локальное сохранение прогресса, возможность возвращаться к любому пройденному уровню в любой момент.

**Шестое.** Списки открытия уровней: уровни 1–5 доступны сразу, уровни 6–10 открываются последовательно по мере прохождения предыдущих. После 10-го уровня открывается «Песочница» — все уровни с полной свободой настроек.

### I.3. Что НЕ делаем

В v4.0 не входят: процедурная генерация уровней, ежедневные челленджи, шаринг реплеев, редактор уровней, монеты и апгрейды, скины, дневные/ночные режимы, магнитные поля, умный разрез троса, динамическая музыка как отдельная система, луч надежды. Они остаются на будущие версии.

### I.4. Инварианты

Что **не меняется** от v3.5.0 ни при каких условиях:

- Физика: гравитация, упругость, трение, CCD-подшаги, коллайдеры.
- Управление: ЛКМ-тяга → наклон, клик/свайп по тросу → разрез, ПКМ → камера, колесо → зум, Space → встряска.
- Магия match-3 (2 → заряд, 3 → взрыв, таймер, кольца).
- Реплей.
- Настройки баланса (4 существующих: скорость, сила ударов, размер, время магии; к ним добавляются 2 новых).
- Локализация RU/EN.
- Внутренние механики: re-wind (шар возвращается на трос), авто-помощь, магнитный ассист, анти-застревание.
- Система очков и комбо (×2…×4).

## Часть II. ТЗ для разработчика

### II.0. Общие требования

Все новые функции добавляются как **надстройка** над существующим кодом. Ничего из ядра (физика, рендеринг, ввод, звук, реплей, локализация) не переписывается. Все новые константы идут в `LEVEL_CONFIG` и `LEVELS`. Все новые строки локализации — в `I18N.ru` и `I18N.en`. Все новые DOM-элементы — с id по существующему стилю (`txt-xxx`, `btn-xxx`, `pill-xxx`). Все новые функции — рядом с родственными по смыслу.

Обозначения в этом ТЗ:
- **П1** — четыре этажа.
- **П2** — числовые лунки (этаж 1).
- **П3** — цепочка в жёлобах (этаж 2).
- **П4** — плиты резонанса (этаж 3).
- **П5** — каскадная магия.
- **П6** — палитры и переходы.
- **П7** — прогрессия 10 уровней.
- **П8** — интерфейс меню и HUD.
- **П9** — настройки и локализация.

### II.1. Архитектурные изменения (П1)

**Цель.** Разбить монолитный уровень v3.5.0 на четыре независимых этажа, каждый со своим состоянием, своей сборкой и своим триггером решения.

#### II.1.1. Состояние мира

Добавить в `W`:

```js
W.currentFloor = 0;                                // 0..3
W.floorState = null;                               // состояние текущего этажа (см. ниже)
W.floorTransition = { active: false, t: 0, dur: 1.2, from: 0, to: 0 };
W.visited = { bowl: false, pipe: false, resonance: false, core: false };
```

`W.floorState` заполняется по-разному на каждом этаже:

```js
// Этаж 1 (лунки)
{ sockets: [ { id, x, z, colorIdx, target, count, locked, mesh, indicator, collider } ] }

// Этаж 2 (цепочка)
{ roads: [ { id, x, z, length, targets: [], mines: [], balls: [], support: [], mesh, targetMesh, indicator, solved, collected } ] }

// Этаж 3 (плиты)
{ plates: [ { id, color, required, range, active, mesh, indicator, collider } ], obstacles: [], modalShown: false }

// Этаж 4 (ядро)
{ coreAlive: true, buttonPressed: false }
```

#### II.1.2. Точка входа

Функция `buildLevel()` сохраняется, но меняется её логика: она теперь собирает **общий каркас** (стакан, трос, свет, фон, декорации) и вызывает `buildFloor(W.currentFloor)` для добавления содержимого этажа.

```js
function buildLevel() {
  applyLevel(W.currentLevel);
  applyFloorPalette(W.currentFloor);
  buildGlassShell();              // стакан, стенки, общий диск
  buildRope();                    // анкер + трос + игровой шар
  buildFloor(W.currentFloor);     // этаж 0..3
  hangPlayer();
  updateHud(0.1, true);
}
```

Функция `buildFloor(idx)` вызывает соответствующую сборку:

```js
function buildFloor(idx) {
  switch (idx) {
    case 0: buildBowlFloor();      break;
    case 1: buildPipeFloor();      break;
    case 2: buildResonanceFloor(); break;
    case 3: buildCoreFloor();      break;
  }
}
```

#### II.1.3. Общие элементы этажа

Каждый `buildXxxFloor` обязан добавить:

- Площадку/пол этажа (меш + коллайдеры).
- Центральный люк на следующий этаж, закрытый заглушкой (`floorGate` — коллайдер с `live = true`, пока этаж не решён).
- Шары и объекты загадки этажа.
- Все визуальные подсказки этажа.

Каждый `buildXxxFloor` заполняет `W.floorState` соответствующими данными.

#### II.1.4. Проверка решения этажа

Функция `checkFloorCondition(dt)` вызывается из `updateTriggers()` и проверяет условие решения текущего этажа:

- Этаж 0: все лунки заполнены (`sockets.every(s => s.count === s.target)`).
- Этаж 1: обе дороги решены (`roads.every(r => r.solved)`).
- Этаж 2: все плиты активны (`plates.every(p => p.active)`).
- Этаж 3: ядро разбито и кнопка нажата (логика v3.5.0, но привязана к этажу 3).

При выполнении условия вызывается `onFloorSolved()`.

#### II.1.5. Решение этажа

Функция `onFloorSolved()`:

1. Отключает `floorGate.live = false`.
2. Играет звук победы этажа.
3. Запускает анимацию открытия заглушки люка (0.6 с).
4. Через 1.5 с — магнитный поток, притягивающий игровой шар к люку (шар движется к центру площадки сам, управление отключается).
5. Шар падает в люк, начинается переход на следующий этаж.
6. Если текущий этаж — последний (индекс 3) — вместо люка вызывается существующая логика победы (`startWin`).

#### II.1.6. Переход между этажами

Состояние `W.floorTransition` активно 1.2 с. Логика:

- `t = 0.0`: звук этажа, запуск анимации.
- `t = 0.0–0.6`: `applyFloorPalette(from)` → `applyFloorPalette(to)` через lerp.
- `t = 0.0–0.6`: `W.cam.tDist` плавно уходит на +10 и возвращается.
- `t = 0.6`: тост «ЭТАЖ 2/4 · ТРУБА» / «FLOOR 2/4 · PIPE» в центре экрана на 1.5 с.
- `t = 1.2`: переход завершён, `W.currentFloor = to`, вызывается `buildFloor(to)`.

Во время перехода физика **активна**, но игровые триггеры этажа (загадки) **приостановлены**.

#### II.1.7. Re-wind и сброс этажа

Существующий `startRewind` работает как и раньше — откатывает игровой шар на трос. Этаж при этом **не пересобирается**. Загадки этажа сохраняют своё состояние.

**Исключение:** если на уровне сложности ≥ 6 (см. П7) игрок провалился, этаж пересобирается полностью (`buildFloor(W.currentFloor)` без смены палитры и без анимации перехода).

#### II.1.8. Что убирается из v3.5.0

Из старого `buildLevel()` убираются конкретные площадки A, B и ядро как отдельные сборки — они становятся частью `buildBowlFloor` (этаж 1) и `buildCoreFloor` (этаж 4). Ядро (этаж 4) полностью сохраняет свою логику v3.5.0, включая три тела-загадки на орбите, орбитальную скорость, разбитие, освобождение тел, шафт-ассист и попадание на кнопку.

Логика воронки (этаж 2 в v3.5.0) **удаляется полностью** — вместо неё этаж 2 в v4.0 использует новую загадку с жёлобами (см. II.3).

### II.2. Этаж 1 «Чаша» — числовые лунки (П2)

#### II.2.1. Геометрия

Площадка этажа 1 — плоский диск на высоте `LEVEL_CONFIG.platformA.y`, полностью сохраняется из v3.5.0 (радиус, толщина, чаша в центре, бортик с выходом на +X, светящиеся кольца). Чаша и бортик используются как «дом» для игрового шара и как пространство для лунок.

**Лунки** — плоские углубления в полу площадки вокруг чаши. Каждая лунка:

- Радиус 1.2, глубина 0.4, толщина 0.2.
- Вкопана в пол площадки, верхний край на уровне пола.
- Позиции: 2–5 лунок в зависимости от уровня сложности (см. II.2.8), расположены по кругу радиусом 6.0 от центра площадки.
- Углы: при 2 лунках — 90°, 270°. При 3 — 90°, 210°, 330°. При 4 — 45°, 135°, 225°, 315°. При 5 — 45°, 117°, 189°, 261°, 333°.

**Центральный люк** — в центре площадки вместо чаши v3.5.0 (чаша остаётся как декоративный элемент под лункой, но люк — новое). Люк радиусом 2.0, заглушка круглым диском радиусом 2.2.

#### II.2.2. Меш лунки

Лунка — Lathe-профиль, вкопанный в пол:

```js
[ [1.2, 0.0], [1.2, -0.4], [1.0, -0.4], [1.0, 0.0], [1.2, 0.0] ]
```

Материал — как `MAT.silverDark`, с эмиссией цвета лунки.

Коллайдер — `makeRevolve` с параметром `e = 0.4` (низкая упругость, чтобы шар не выпрыгивал).

#### II.2.3. Число над лункой

Над каждой лункой висит billboard-спрайт (CanvasTexture на плоскости 1.6 × 1.6):

- Цифра-цель (1, 2, 3, 4, 5), цвет = `socket.colorIdx`-цвет.
- Под цифрой — горизонтальная полоска прогресса `count / target`.
- Цифра меняет цвет на зелёный, когда `count === target`.

Billboard обновляется каждый кадр (переиспользовать `billboard()` из v3.5.0).

#### II.2.4. Логика зачисления

Событие: игровой шар или цветной шар касается дна лунки (`ball.p.y < socket.y + ball.r` и `ball.p.xz` внутри радиуса лунки).

Проверка:
1. Если `socket.locked === true` — ничего не происходит, шар отскакивает.
2. Если `ball.colorIdx !== socket.colorIdx` — шар вылетает обратно (импульс вверх 3 м/с), звук `Sound.fade()`, тост «Не тот цвет» / «Wrong colour».
3. Если `socket.count >= socket.target` — шар вылетает обратно, звук `Sound.fade()`, тост «Перебор» / «Too many».
4. Иначе:
   - `socket.count++`.
   - Игровой/цветной шар **закрепляется** в лунке: `ball.kinematic = true`, `ball.mountPos` = центр лунки, шар остаётся там до конца этажа.
   - Звук `Sound.charge()`.
   - Вспышка цвета лунки.
   - Если `socket.count === socket.target` — лунка становится зелёной, `socket.locked = true`, её коллайдер отключается (`live = false`), тост «Лунка заполнена» / «Socket filled».

#### II.2.5. Магия и лунки

Если шар, закреплённый в лунке, попадает в магию match-3 (совпал по цвету с двумя другими свободными) — магия срабатывает как обычно, шар взрывается, `socket.count--`, если он был засчитан. Это создаёт риск: игрок может случайно сломать собственную лунку.

Чтобы избежать неумышленного срабатывания, шары, закреплённые в лунке, **не участвуют** в `Magic.components()`. Флаг `ball.inSocket = true` (или аналогичный), и `Magic.components()` фильтрует их.

#### II.2.6. Магнитные шары этажа 1

Магнитные шары из v3.5.0 (R-A, B-A, Y-A, Lone-A1, Lone-A2) **сохраняются** на этаже 1 как «источник» шаров для лунок. Их расположение на площадке не меняется. Игрок может освободить их касанием игрового шара или встряской, чтобы они покатились и могли попасть в лунки.

Магнитные шары с флагом `noMagic: false` участвуют в магии как раньше.

#### II.2.7. Обучающая подсказка

При первом появлении игрока на этаже 1 (`W.visited.bowl === false`):

- Тост «Закати в каждую лунку столько шариков своего цвета, сколько написано» / «Roll into each socket as many balls of its colour as written» на 4 с.
- Каждая лунка пульсирует своим цветом 3 раза.
- `W.visited.bowl = true`.

#### II.2.8. Параметры по уровням сложности

| Уровень | Лунок | Числа (target) | Цвета (colorIdx) |
|---|---|---|---|
| 1 | 1 | [1] | [red] |
| 2 | 2 | [1, 2] | [red, blue] |
| 3 | 2 | [2, 2] | [red, yellow] |
| 4 | 3 | [1, 2, 3] | [red, blue, yellow] |
| 5 | 3 | [2, 3, 3] | [red, red, blue] |
| 6 | 3 | [3, 3, 4] | [red, blue, yellow] |
| 7 | 4 | [2, 3, 3, 4] | [red, blue, yellow, yellow] |
| 8 | 4 | [2, 3, 4, 4] | [red, blue, yellow, red] |
| 9 | 4 | [3, 3, 4, 4] | [red, blue, yellow, yellow] |
| 10 | 5 | [2, 3, 3, 4, 5] | [red, blue, yellow, red, yellow] |

#### II.2.9. Условие решения этажа 1

Все лунки имеют `count === target`. При выполнении — открывается центральный люк.

### II.3. Этаж 2 «Труба» — цепочка в жёлобах (П3)

#### II.3.1. Геометрия

Площадка этажа 2 — плоский диск на высоте `LEVEL_CONFIG.platformB.y`. Воронка v3.5.0 **удаляется полностью**. Площадка плоская, с двумя вкопанными жёлобами.

**Жёлобы** — два U-образных профиля в полу:

- **Дорога A**: центр по X = −3.0, по Z = +2.0. Длина 12.0, ширина 1.5, глубина 0.6. Ориентация вдоль оси X. Вход на X = −9.0, выход на X = +3.0.
- **Дорога B**: центр по X = +3.0, по Z = −2.0. Длина 10.0, ширина 1.5, глубина 0.6. Вход на X = −2.0, выход на X = +8.0.

Дороги не пересекаются, разнесены по Z на 4.0.

Уклон жёлоба: 3° в сторону выхода (шар катится сам после толчка).

**Профиль жёлоба** (в разрезе):

```js
[ [-0.75, 0.0], [-0.75, -0.6], [0.75, -0.6], [0.75, 0.0] ]
```

Материал: `MAT.silverDark` с подсветкой по краю.

**Коллайдеры жёлоба**: три `makeRevolve`-секции (левый борт, дно, правый борт) с `e = 0.5`.

#### II.3.2. Спусковые люки

Над входом каждой дороги — круглое отверстие в полу площадки:

- Люк A: центр X = −9.0, Z = +2.0, радиус 1.2.
- Люк B: центр X = −2.0, Z = −2.0, радиус 1.2.

Край люка подсвечен цветом целевого шара (см. II.3.3).

Коллайдер люка: `makeRevolve` с `e = 0.3` — открытый проём, шар падает внутрь.

#### II.3.3. Целевой цвет

На каждом прохождении этажа 2 **обе дороги ждут шары одного и того же цвета**. Цвет задаётся конструктором уровня (см. II.3.11) и хранится в `W.floorState.roads[i].colorIdx`.

Цвет виден по подсветке люков и мишеней.

#### II.3.4. Приёмные мишени

На выходе каждой дороги — цилиндрическая лунка радиусом 1.4, глубиной 0.8, на уровне дна жёлоба.

- Мишень A: X = +3.0, Z = +2.0.
- Мишень B: X = +8.0, Z = −2.0.

Над каждой мишенью — billboard-цифра `collected / targets` размером 1.6, цвет = цвет целевого шара.

Коллайдер мишени: `makeRevolve` с `e = 0.2`.

#### II.3.5. Содержимое жёлоба

В каждом жёлобе — фиксированная линейка шаров. Типы:

- **К** — целевой, цвет `colorIdx`.
- **С** — случайный-нейтральный, цвет red/blue/yellow, кроме целевого.
- **М** — мина, белый шар (colorIdx = −1) с крестиком.

Каждый шар линейки — обычная `Ball` с флагами:

```js
{
  mounted: false,        // не примагничен, но стоит на опоре
  inChain: true,         // участвует в цепочке
  noMagic: true,         // не участвует в магии
  chainIdx: 0,           // порядковый номер в цепочке
  roadId: 'A' | 'B',     // к какой дороге относится
}
```

Шары стоят на **опорах-носиках** — маленьких сферах-коллайдерах (радиус 0.15) под каждым шаром. Коллайдер опоры `live = true`, пока шар не толкнут.

Между соседними шарами — зазор 0.05 юнита.

#### II.3.6. Запуск цепочки

1. Игровой шар катится по площадке, попадает в люк (через наклон стакана).
2. Падает в жёлоб на входе и катится в сторону выхода (уклон 3°).
3. Касается первого шара линейки.
4. Для первого шара: `ball.v.y` сработал, толчок передан. Опоры первого шара отключается (`live = false`).
5. Первый шар катится вперёд, толкает второй — и так далее.
6. Каждый шар на выходе попадает в мишень. Мишень определяет тип шара и реагирует:
   - К: `collected++`, звук `Sound.charge()`, вспышка целевого цвета.
   - С: игнорируется, шар исчезает через 0.3 с после касания дна мишени.
   - М: срабатывает ошибка (см. II.3.7).
7. **Игровой шар** после запуска катится вместе с цепочкой и попадает в мишень как С, исчезает через 0.3 с.

Если игровой шар попадает в люк уже решённой дороги — ничего не происходит, шар выкатывается в ловушку.

#### II.3.7. Обработка ошибки (мина)

При касании мины дна мишени:

1. Звук `Sound.trap()`.
2. Тост «Мина! Цепочка порвана» / «Mine! Chain broken» на 2 с.
3. **Все шары этой дороги** (включая уже прокатившиеся, но не засчитанные) телепортируются на исходные позиции, опоры включаются (`live = true`).
4. `road.collected = 0`, мишень возвращается в исходное состояние.
5. Вторая дорога не затрагивается.
6. Через 1.2 с дорога готова к новому запуску.

#### II.3.8. Решение этажа 2

Когда `roads.every(r => r.collected === r.targets)`:

1. Звук победы этажа.
2. Обе мишени светятся зелёным постоянно.
3. Открывается центральный люк на этаж 3 (см. II.1.5).

#### II.3.9. Визуальные подсказки

Над каждой дорогой — горизонтальная полоска прогресса мишени (`collected / targets`) целевым цветом. Над мишенью — крупная цифра того же счёта.

Над каждым шаром жёлоба — маленький индикатор:
- К — цветная точка цвета шара.
- М — белый крестик.
- С — ничего.

Подсветка люков цветом мишени соответствующей дороги.

#### II.3.10. Кнопка «Сбросить цепочки»

В HUD (правый верхний угол) появляется кнопка **«Сбросить цепочки» / «Reset chains»**, доступная только когда `W.currentFloor === 1`.

По нажатию: обе дороги пересобираются (шары на позициях, опоры включены, мишени обнулены, счётчики сброшены). Не влияет на очки и попытки. Тост «Цепочки пересобраны» / «Chains reset».

#### II.3.11. Параметры по уровням сложности

| Уровень | Дорога A | Дорога B | Всего нужно | Мин | Смещение |
|---|---|---|---|---|---|
| 1 | 3: 2К 1С 0М | — | 2 | 0 | нет |
| 2 | 4: 2К 1С 1М | — | 2 | 1 | нет |
| 3 | 5: 2К 2С 1М | 3: 1К 2С 0М | 3 | 1 | нет |
| 4 | 5: 3К 1С 1М | 4: 1К 2С 1М | 4 | 2 | нет |
| 5 | 6: 3К 2С 1М | 5: 2К 2С 1М | 5 | 2 | нет |
| 6 | 6: 3К 2С 1М | 5: 2К 2С 1М | 5 | 2 | нет |
| 7 | 7: 3К 3С 1М | 6: 2К 3С 1М | 5 | 2 | нет |
| 8 | 7: 3К 3С 1М | 6: 3К 2С 1М | 6 | 2 | нет |
| 9 | 8: 4К 3С 1М | 7: 3К 3С 1М | 7 | 2 | нет |
| 10 | 8: 4К 3С 1М | 7: 3К 3С 1М | 7 | 3 | да, ±0.15 по Z |

На уровнях 7–10 порядок шаров — «хитрый»: мина может стоять между двумя целевыми. Общее правило — игрок всегда может решить дорогу, если правильно считает порядок. Мины никогда не стоят так, чтобы сделать решение невозможным.

На уровне 10 — случайное смещение шаров по Z ±0.15, из-за чего цепочка может «заедать» и требовать дополнительного толчка.

#### II.3.12. Флаги шаров цепочки в контексте магии

Шары цепочки имеют `noMagic: true`. Функция `Magic.components()` их пропускает — они не участвуют ни в основном взрыве, ни в эхо-магии (см. II.5).

### II.4. Этаж 3 «Резонанс» — плиты на полу (П4)

#### II.4.1. Геометрия

Площадка этажа 3 — плоский диск радиусом 8.0 на высоте `LEVEL_CONFIG.resonance.y` (для каждого из 10 уровней сложности — своя, см. II.4.13).

**Центральный люк** — круглое отверстие радиусом 2.0 в центре площадки. Заглушка — плоский диск радиусом 2.2, толщиной 0.15, лежит сверху.

**Три плиты** — квадраты 1.2 × 1.2, толщиной 0.4, вкопанные в пол на уровне `y + 0.05`:

- Зелёная плита: X = 0, Z = −4.0.
- Жёлтая плита: X = 3.46, Z = +2.0.
- Красная плита: X = −3.46, Z = +2.0.

Три плиты образуют треугольник вокруг люка на равной дистанции 4.0 от центра.

#### II.4.2. Меш плиты

Плита — `BoxGeometry(1.2, 0.4, 1.2)` или `PlaneGeometry` + экструзия. Материал — как `MAT.core`, цвет соответствует требуемой силе:

- Зелёная: `0x00ff88`.
- Жёлтая: `0xffcc00`.
- Красная: `0xff3355`.

При активации плита светится зелёным `0x00ff88` постоянно (эмиссия 2.0).

При деактивации плита гаснет (`emissiveIntensity = 0`).

Коллайдер — `makeRevolve` или `makeCapsule`, `e = 0.6` (шар отскакивает).

#### II.4.3. Целевая сила удара

| Плита | Цвет | Требуемая сила | Порог скорости, м/с |
|---|---|---|---|
| Зелёная | `0x00ff88` | Слабо | `0.4 – 2.0` (базовый) |
| Жёлтая | `0xffcc00` | Средне | `2.5 – 5.0` (базовый) |
| Красная | `0xff3355` | Сильно | `6.5 – 10.0` (базовый) |

Пороги уточняются по уровням сложности (см. II.4.13).

#### II.4.4. Логика взаимодействия с игровым шаром

1. Игровой шар катится или летит, приближается к боковой грани плиты.
2. В момент касания фиксируется `ball.impact` (уже считается в физике v3.5.0).
3. Если `impact` в диапазоне плиты:
   - Если плита уже `active` — ничего (уже активна).
   - Иначе: `plate.active = true`, эмиссия 2.0, звук `Sound.charge()`, тост «Плита активна» / «Plate active», вспышка.
4. Если `impact` меньше нижнего порога:
   - Плита мигает серым 0.4 с, звук `Sound.fade()`, тост «Слабо» / «Too weak».
   - Шар отскакивает, теряет 30% скорости.
5. Если `impact` больше верхнего порога:
   - Плита мигает серым 0.4 с, звук `Sound.fade()`, тост «Сильно» / «Too strong».
   - Шар отскакивает, теряет 10% скорости.

#### II.4.5. Логика взаимодействия с другими шарами

Плиты реагируют на удары любых шаров, кроме игрового. Другие шары — свободные цветные шары, шары-помехи, освобождённые магнитные шары.

При касании другого шара:

1. Фиксируется `ball.impact`.
2. Если `impact` в диапазоне плиты:
   - Если плита активна → **деактивируется**: `plate.active = false`, эмиссия 0, звук `Sound.defeat()`, экранный шейк 0.3 с.
   - Если плита не активна → активируется (как если бы ударил игровой шар).
3. Если `impact` вне диапазона — шар просто отскакивает.

#### II.4.6. Деактивация и модальное окно

При **первой** деактивации плиты на текущем прохождении этажа (флаг `W.floorState.modalShown === false`) вызывается модальное окно:

**Заголовок:** «Плита деактивирована» / «Plate deactivated».

**Описание:** «Шар не того цвета ударил по плите и сбросил её. Начать этаж заново или выйти в меню?» / «A wrong ball hit the plate and reset it. Restart the floor or return to the menu?»

**Кнопки:**
- «Начать заново» / «Restart floor» — пересобирает этаж 3 полностью.
- «В меню» / «To menu» — возвращает в главное меню, прогресс этажа теряется.

После первого показа флаг `modalShown = true`, и модальное окно больше не появляется. Вместо него — только тост «Плита деактивирована» / «Plate deactivated».

#### II.4.7. Кнопка «Начать этаж заново»

В HUD на этаже 3 (правый верхний угол) появляется кнопка **«Начать этаж заново» / «Restart floor»**, доступная только когда `W.currentFloor === 2`.

По нажатию: этаж пересобирается (плиты, помехи, игровой шар возвращается на верхнюю точку). Тост «Этаж пересобран» / «Floor restarted».

Кнопка доступна всегда на этаже 3, независимо от модального окна.

#### II.4.8. Шары-помехи

Для реальной угрозы деактивации на этаже есть шары-помехи:

- **Уровни 1–5:** помех нет.
- **Уровни 6–8:** 1 помеха, расположена на расстоянии 3–4 юнита от ближайшей плиты.
- **Уровни 9–10:** 2 помехи, симметрично с двух сторон площадки.

Шары-помехи — обычные `Ball` с флагами:

```js
{
  mounted: false,
  isObstacle: true,
  noMagic: false,        // участвуют в магии
}
```

При столкновении двух помех друг с другом — срабатывает магия, если они одного цвета. Это не деактивирует плиты напрямую, но может случайно столкнуть шар к плите с достаточной силой.

При падении помехи в открытый люк — она падает на этаж 4 и исчезает.

#### II.4.9. Решение этажа 3

Когда все три плиты активны одновременно:

1. Звук победы этажа.
2. Все плиты светятся зелёным.
3. Заглушка люка открывается (0.6 с).
4. Магнитный поток к люку (см. II.1.5).

#### II.4.10. Re-wind на этаже 3

Существующий `startRewind` работает как обычно. Активированные плиты сохраняются. Деактивированные плиты остаются деактивированными.

#### II.4.11. Визуальные подсказки

Над каждой плитой — billboard-индикатор:
- Цифра 1, 2 или 3 в правом верхнем углу (номер плиты).
- Полоска под цифрой: пустая (деактивирована), серая (неактивна), зелёная (активна).
- Мигание серым при неудачном ударе.

Над люком — billboard-индикатор с тремя квадратиками (по одному на плиту): пустые (неактивные), зелёные (активные). Когда все три зелёные — люк открывается.

При первом появлении игрока на этаже 3:
- Тост «Бей плиты своим шаром: слабо — зелёную, средне — жёлтую, сильно — красную» / «Hit plates with your ball: weak — green, mid — yellow, strong — red» на 4 с.
- Каждая плита пульсирует своим цветом 3 раза.
- `W.visited.resonance = true`.

#### II.4.12. Приоритет при одновременном ударе

Если игровой и другой шар одновременно касаются плиты, приоритет отдаётся игровому. Если его `impact` в диапазоне — плита активируется. Деактивация другим шаром в этот же кадр не срабатывает.

#### II.4.13. Параметры по уровням сложности

| Уровень | Пороги слабо | Пороги средне | Пороги сильно | Помех |

| 3 | 0.4–2.0 | 2.5–5.0 | 6.5–10.0 | 0 |
| 4 | 0.6–1.6 | 2.5–4.8 | 6.5–10.0 | 0 |

### II.5. Каскадная магия (П5)

#### II.5.1. Правило каскада

После взрыва цепочки из 3+ шаров одного цвета (`Magic.explode`) запускается проверка на эхо: если в радиусе `SETTINGS.echoRadius` (по умолчанию 3.5) от центра взрыва есть другие свободные шары того же цвета — они становятся вторым звеном каскада.

Каскад — **максимум два звена**: основное + одно эхо. Эхо не порождает новое эхо.

#### II.5.2. Логика

```js
function echoCheck(comp) {
  if (comp[0].isEcho) return;
  const colorIdx = comp[0].colorIdx;
  let cx = 0, cy = 0, cz = 0;
  for (const b of comp) { cx += b.p.x; cy += b.p.y; cz += b.p.z; }
  cx /= comp.length; cy /= comp.length; cz /= comp.length;
  const found = [];
  for (const b of W.balls) {
    if (!b.alive || b.kinematic) continue;
    if (b.colorIdx !== colorIdx) continue;
    if (comp.indexOf(b) >= 0) continue;
    if (b.inSocket || b.noMagic || b.inChain) continue;
    const dx = b.p.x - cx, dy = b.p.y - cy, dz = b.p.z - cz;
    if (dx*dx + dy*dy + dz*dz < SETTINGS.echoRadius * SETTINGS.echoRadius) {
      found.push(b);
    }
  }
  if (found.length === 0) return;
  // Задержка визуальной «волны»
  W.floorState.echoPending = {
    t: SETTINGS.echoWindow,
    comp: found,
  };
}
```

В `updateTriggers` или в цикле магии — когда `echoPending.t <= 0`, вызывается `Magic.explode(found)` с флагом `isEcho = true`.

#### II.5.3. Очки

- Основной взрыв: `400 + extra * 100`, с учётом combo.
- Эхо-взрыв: `250 + extra * 60`, без наложения combo (combo остаётся от основного взрыва).

#### II.5.4. Визуальные и звуковые эффекты

- Эхо-взрыв: shockwave меньшего размера (0.7× от основного) со сдвигом цвета на 0.1 в HSL; искры на 40% меньше, но с большей скоростью и затуханием.
- Звук: то же арпеджио `Sound.boom`, но сдвинутое на октаву выше и с amplitude × 0.7.
- Тост «КАСКАД +N» / «CASCADE +N».

#### II.5.5. Ограничение на уровнях сложности

Эхо-магия работает со 2-го уровня сложности (не на 1-м, чтобы не пугать новичка).

#### II.5.6. Настройки

Добавить в панель настроек два новых слайдера:

- 5) **Радиус эха** / **Echo radius**: 2.0–6.0, шаг 0.1, default 3.5. Сохраняется в `SETTINGS.echoRadius`.
- 6) **Окно эха** / **Echo window**: 0.1–0.6 с, шаг 0.05, default 0.25. Сохраняется в `SETTINGS.echoWindow`.

Оба — в существующий блок `SETTINGS_LIMITS`.

### II.7. Прогрессия 10 уровней (П7)

#### II.7.1. Структура

10 уровней сложности. Каждый уровень содержит все четыре этажа в фиксированном порядке: Чаша → Труба → Резонанс → Ядро.

Уровни различаются параметрами загадок (см. II.2.8, II.3.11, II.4.13) и порогами (II.4.13), а также модификаторами (II.7.3).

#### II.7.2. Доступ

- Уровни 1–5 доступны с самого начала.
- Уровни 6–10 открываются последовательно: пройти уровень N → открывается N+1. Без требований к звёздам и очкам.
- После прохождения 10-го — открывается «Песочница»: все уровни с полной свободой настроек.

#### II.7.3. Модификаторы по уровням

| Уровень | Время магии | Re-wind | Perfect cut | Особое |
|---|---|---|---|---|
| 1 | 10 с | свободно | не требуется | обучающий |
| 2 | 10 с | свободно | не требуется | — |
| 3 | 10 с | свободно | не требуется | — |
| 4 | 9 с | свободно | не требуется | эхо-магия включена |
| 5 | 8 с | штраф −50 | не требуется | — |
| 6 | 7 с | сброс этажа | не требуется | — |
| 7 | 6 с | сброс этажа | не требуется | смещение цепочки |
| 8 | 5 с | сброс этажа | требуется | трос значим |
| 9 | 4 с | штраф −100 | требуется | узкие окна, помехи |
| 10 | 3 с | штраф −200 | требуется | ядро усилено (4 тела), 2 помехи |

**«Свободно»** — re-wind работает как в v3.5.0 (шар откатывается на трос, этаж не пересобирается).

**«Сброс этажа»** — при падении в ловушку этаж пересобирается полностью (загадки сбрасываются).

**«Штраф −N»** — при использовании re-wind отнимается N очков (но не меньше нуля).

**«Требуется perfect cut»** — если резать не в идеальной зоне, шар получает −10% к стартовой скорости. Ошибка не критична, но сказывается.

**«Ядро усилено»** — 4 тела на орбите вместо 3, скорость орбиты +20%.

Названия видны в меню уровней и в HUD при старте уровня.

#### II.7.5. Рестарт уровня

При прохождении игры заново (кнопка «Играть снова» из модалки победы) — текущий уровень перезапускается.

При выборе другого уровня из меню — `W.currentLevel` меняется, `buildLevel()` пересобирается, `W.currentFloor = 0`.

#### II.7.6. Прогресс

Все 10 уровней хранят: время, очки, звёзды, статус рекорда. Сохраняются в `localStorage` под ключами:

- `graviboom_v4_levels` — JSON с массивом из 10 объектов `{ time, score, stars }`.
- `graviboom_v4_bestScore` — общий рекорд очков.
- `graviboom_v4_unlocked` — массив булевых «какие уровни открыты».

#### II.7.7. Что сохраняется

- Время лучшего прохождения каждого уровня.
- Очки лучшего прохождения.
- Звёзды (1–3).
- Общий рекорд очков.
- Список открытых уровней.

#### II.7.8. Реиграбельность

Каждый уровень можно проходить сколько угодно раз:
- Для сбора 3 звёзд (победа + время < 60 с + без ошибок).
- Для улучшения рекорда очков.
- Для попытки челленджа (опционально, только после 3 звёзд).

После прохождения уровня на 3 звезды открывается **челлендж уровня** — модификатор, отображаемый в меню уровней:
- 1: без магии.
- 2: без re-wind.
- 3: не использовать встряску.
- 4: время < 45 с.
- 5: не потерять ни одного шара.
- 6: без perfect cut.
- 7: не использовать кнопку сброса цепочек.
- 8: не использовать кнопку рестарта этажа.
- 9: не использовать трос дважды.
- 10: без подсказок.

15 челленджей — по одному на уровень плюс 5 специальных, открывающихся после 3 звёзд на 10-м уровне. Все опциональны.

### II.10. Интеграционные моменты

#### II.10.1. Совместимость с существующей системой `LEVELS`

Существующий массив `LEVELS[0..4]` из v3.5.0 (5 элементов с нарастающей сложностью) **расширяется до 10 элементов** в соответствии с II.7.3. Поля каждого элемента:

```js
{
  id: 1,
  // Уровень 1: только лунка, только одна дорога, только одна плита
  bowl: { sockets: [ { colorIdx, target } ], ... },
  pipe: { roads: [ ... ], ... },
  resonance: { plates: [ ... ], obstacles: 0, ... },
  core: { orbitBodies: 3, orbitSpeedK: 1.0 },
  magicTime: 10.0,
  rewindCost: 0,
  rewindResetsFloor: false,
  perfectCutRequired: false,
  ...
}
```

#### II.10.2. Совместимость с существующим `buildLevel`

Старый `buildLevel` из v3.5.0 разбирается на:

- `buildGlassShell()` — стакан, стенки, пояса, обод.
- `buildRope()` — анкер + трос + игровой шар.
- `buildFloor(0..3)` — собственно этажи.

Логика `buildLevel` (внешняя) сохраняется, но переопределяется.

#### II.10.3. Совместимость с `Replay`

`Replay.record()` продолжает записывать спуск с частотой 40 Гц. При переходе между этажами сэмпл записывается с флагом `floor`, чтобы при воспроизведении реплей корректно переключал палитру.

`Replay.start()` воспроизводит как обычно. Этаж в реплее не пересобирается, только визуальные палитры переключаются.

#### II.10.4. Совместимость с `Magic`

`Magic.components()` фильтрует:

- Шары цепочки (`ball.inChain`).
- Шары в лунках (`ball.inSocket`).
- Примагниченные шары (`ball.mounted`, `ball.kinematic`).
- Шары, помеченные `noMagic`.

`Magic.explode()` дополняется вызовом `echoCheck` (см. II.5).

#### II.10.5. Совместимость с `Sound`

Все новые звуки — через существующие методы `_tone`/`_noise`. Никаких новых файлов. Звук победы этажа — короткое арпеджио C-E-G одной октавой выше `Sound.victory`.

### II.11. Тестирование и критерии готовности

#### II.11.1. Функциональные тесты

1. Все 10 уровней проходятся от начала до конца без перезагрузки страницы.
2. На каждом уровне все 4 этажа решаются и люки открываются.
3. Re-wind не сбрасывает решённые загадки, но сбрасывает незавершённые (цепочка на этаже 2).
4. Плиты на этаже 3 активируются и деактивируются как описано.
5. Модальное окно «Плита деактивирована» появляется только один раз за этаж.
6. Каскадная магия срабатывает, максимум 2 звена.
7. Палитры переключаются плавно при переходе между этажами.
8. Прогресс сохраняется в `localStorage` между сессиями.

#### II.11.2. Пользовательские сценарии

1. Игрок запускает игру, видит меню с 10 уровнями (1–5 открыты, 6–10 заблокированы).
2. Проходит уровень 1, собирает 3 звезды, видит рекорд очков.
3. Возвращается в меню, видит уровень 2 открытым.
4. Пробует уровень 3, падает на этаже 2 из-за мины, видит пересборку цепочки.
5. На уровне 6 случайно сталкивает шар-помеху к плите, видит модальное окно, выбирает «Начать этаж заново».
6. На уровне 9 собирает 3 звезды, разблокирует челлендж.
7. Проходит уровень 10, получает доступ к «Песочнице».

#### II.11.3. Производительность

- FPS не ниже 45 на среднем смартфоне (iPhone SE 2 / Samsung A52).
- Все переходы этажей не вызывают утечек памяти (`disposeGroup` корректно чистит старые меши).
- Загрузка страницы не более 3 с на 3G.

#### II.11.4. Мобильная вёрстка

- Индикатор этажа в HUD не перекрывает остальные таблетки.
- Кнопка «Сбросить цепочки» и «Начать этаж заново» не закрывают игровой шар.
- Модальное окно «Плита деактивирована» влезает без прокрутки на экран 360×640.

#### II.11.5. Локализация

- Все новые ключи заполнены в RU и EN.
- Переключение языка обновляет все новые элементы.
- Никаких «undefined» в UI.

#### II.11.6. Совместимость с существующими системами

- Существующая физика не меняется.
- Существующая магия match-3 работает как раньше, плюс каскад.
- Существующий реплей работает.
- Существующие 4 настройки работают. Плюс 2 новых.

#### II.11.7. Критерии готовности

Релиз v4.0 считается готовым, когда:

- Все 10 уровней пройдены тестировщиком от начала до конца.
- Все новые механики работают.
- Ни одна загадка не ломает физику.
- Палитры и переходы плавные.
- HUD показывает всё нужное.
- Локализация полная.
- Модальные окна появляются корректно.
- Прогресс сохраняется.
- Мобильная вёрстка не сломана.
- Производительность в норме.
